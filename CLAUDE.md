## Commands

```bash
pnpm install
pnpm dev       # http://localhost:4321 — Astro 7 daemonizes; see below
pnpm build     # astro check && astro build → dist/  (38 pages)
pnpm lint      # oxlint
```

`pnpm dev` **returns immediately** — Astro 7 backgrounds the server and it
survives the shell that started it. Manage it with `pnpm exec astro dev status`
/ `logs` / `stop`, not by killing the foreground process.

pnpm 11 keeps settings in `pnpm-workspace.yaml`, not `package.json`. A
`pnpm.onlyBuiltDependencies` key in `package.json` is silently ignored; esbuild's
postinstall is allowed via `allowBuilds` in the workspace file.

## Invariants

Breaking any of these breaks the model the site is built on. All five are
explained in ARCHITECTURE.md §12.

1. **Nothing becomes an island unless it holds state.** Animation is not a
   reason to hydrate.
2. **Filters never re-render.** Every card ships in the HTML; the filter toggles
   `hidden`. The crawler must see the whole catalogue.
3. **Never hand-edit `src/ds/tokens/`.** It is a literal copy from Claude
   Design; edits are lost on re-sync. Override in `src/styles/app.css`.
4. **Motion is additive.** GSAP loads on idle and not at all under
   reduced-motion. The page must be complete and correct with JS off.
5. **Game and score data never becomes Markdown.** Editorial content is
   Markdown; game data comes from APIs.

## Where things are

```
src/
  pages/            one file per route; [slug].astro for detail pages
  layouts/Base      <head> per page — title, description, canonical, OG, ogType
  content/          reviews · news · guides in Markdown
  content.config.ts Zod schemas; validated on every build
  ds/               design system — tokens are generated, do not hand-edit
  components/       .astro, zero client JS
  islands/          the only two React components that hydrate
  scripts/          motion.ts (GSAP, data-attribute driven) · filters.ts
  data/games.ts     homepage seed data (games.ts is live; the other three are dead)
```

## What is placeholder

Do not treat any of this as real:

- **Every word of editorial copy** — verdicts, headlines, critic names, studios.
- **All game data**, including scores and source counts. Non-2026 years are
  generated by a seeded PRNG.
- **`sourceCount`** — the page prints "based on 51 sources" with no source table
  behind it. The aggregate is a claim, not a computation (SCHEMA.md §4).
- **Cover art** — flat gradient fills from `GRADIENTS`, standing in for IGDB/RAWG.

## Current state

Built: homepage, three section indices, 34 article detail pages, the motion and
filter systems, and a cross-device pass verified from 320px to 2560px.

Not built: the game detail page (design chosen — direction A — but blocked on
the score model), the score system itself, `/api/recommend`.

Deployed to https://sibi-gamers.vercel.app. The canonical URLs still say
`sibigamers.gg`, a domain that is not attached yet — a known, deliberate gap.

Game links in the islands still point at `#` and are the only remaining
sub-44px touch targets; they need the stretched-link treatment when the route
exists.

## Conventions

- Match the surrounding code's comment density — comments here explain *why*,
  not what.
- New CSS goes in `src/styles/app.css` using tokens; no raw hex values.
- Content-driven breakpoints, not device names. Touch sizing keys off
  `pointer: coarse`, never width.
- `astro check` runs before every build, so type errors fail the build.
- **No emojis** anywhere: docs, code, comments, commit messages, UI copy.
- Keep prose concise. Say the thing, stop.
